## Today's developments

### 1. Trustworthy RAG: An Evaluation Agent for Detecting Misinformation and Knowledge Poisoning in Generative AI Systems (academic, Balkrishna Giri, Md Toufique Hasan, Jussi Rasku, Muhammad Waseem, Pekka Abrahamsson, 2026-08-24)

**Why it matters:** High semantic relevance between a retrieved passage and a query does not guarantee factual truth — similarity-based retrieval alone cannot catch knowledge poisoning. This paper names a concrete middleware pattern (NLI fact-checking + a five-signal poison detector + a Trust Index) to insert between retrieval and generation, with quantified detection rates (91% accuracy, 100% instruction-injection recall, ROC-AUC 0.73–0.81) a team could use as a baseline when hardening a RAG pipeline for research or policy use.

**Source:** https://arxiv.org/abs/2608.21095 · **Library entry:** [2026-giri-trustworthy-rag-poison-detection](../../../library/entries/2026-giri-trustworthy-rag-poison-detection.md)
**Selected because:** directly on the profile's standing lens — making RAG-grounded outputs defensible, not just plausible — with a named, quantified mechanism.

### 2. Beyond Fault Localization: A Trajectory-Level Study of LLM Agents for Microservice Root Cause Analysis (academic, Qisheng Lu, Aoyang Fang, Junjielong Xu, Jin'ao Shang, Songhan Zhang, Yifan Yang, Xiaochuan Yan, Pinjia He, 2026-08-24)

**Why it matters:** An agent can name the correct root cause while still failing to reconstruct how the fault actually propagated — answer correctness and diagnostic quality are separable, and evaluating only the former hides this. The paper's two-stage defense-in-depth fix (ground before localizing, then verify against the evidence) raised Acc@1 from 43.5% to 52.5% in an independent test setting, and the underlying warning generalizes to any agentic system judged only by its final answer.

**Source:** https://arxiv.org/abs/2608.21310 · **Library entry:** [2026-lu-diagguard-trajectory-rca](../../../library/entries/2026-lu-diagguard-trajectory-rca.md)
**Selected because:** a transferable observability/debugging lesson (lens 5) with a concrete architecture and cross-setting validated improvement.

### 3. Temporal Validity on Real Software Histories: Eliminating Stale-Fact Errors in Code-Assistant Memory over GitHub Fixes (academic, Neeraj Yadav, 2026-08-24)

**Why it matters:** Standard RAG-based code-assistant memory can't tell a superseded fact from a current one mid-session, and served stale values 36–38% of the time in this study. Tracking state transitions deterministically instead of retrieving by similarity cut that to roughly zero (0.91 vs. 0.57–0.59 accuracy) at no latency cost — a specific, bounded case (the paper reports it covers about 18% of real fixes) for when deterministic memory should replace retrieval.

**Source:** https://arxiv.org/abs/2608.20685 · **Library entry:** [2026-yadav-memstrata-temporal-validity](../../../library/entries/2026-yadav-memstrata-temporal-validity.md)
**Selected because:** a quantified, harness-engineering-lens (lens 2) fix for a common and previously unmeasured agent-memory failure mode.
