### 1. What a Random Draw from the MCP Registry Contains, and What Tool-Use Benchmarks Contain Instead (academic, Haseeb Mohammed Afsar, arXiv, 2026-09-10)

**Why it matters:** A random sample of 400 MCP servers from a 24,135-server registry completes an `initialize` handshake only 48.8% of the time, versus 66.7% for hand-curated samples — evidence that curated MCP demos overstate real-world integration reliability. Widely used tool-use benchmarks (BFCL v4, UltraTool) also contain far more near-duplicate and exact-repeat tool definitions than the real ecosystem does, which likely inflates measured tool-selection accuracy. Both findings are directly actionable for MCP integration planning and eval design.

### 2. Engineering Reliable Commit Gates for Agentic AI: Cost-Aware Verification Portfolios under Common-Mode Data Failures (academic, Zihao Zheng, Baichuan Li, Junyi Yao, Jiayu Long, arXiv, 2026-09-10)

**Why it matters:** VP-CONTROL, tested across 2,880 scenarios in six fault regimes, shows that a cross-model vote over *shared* evidence approves 62.9% of unsafe agent proposals versus 22.9% when verifiers draw on *independent* evidence — meaning multiple verifier models alone are a weak defense against common-mode failures. Their adaptive portfolio controller reaches ~1.9% unsafe-execution rate, and a 216-episode database test shows full atomic guards (not partial transactional guards) are needed to prevent all unsafe effects. A direct, quantified warning for anyone building multi-verifier guardrails around agent actions.

**Source:** https://arxiv.org/abs/2609.10969 · **Library entry:** [2026-zheng-vp-control-commit-gates](../../../library/entries/2026-zheng-vp-control-commit-gates.md)
**Selected because:** a named common-mode-failure mechanism and a quantified fix for verification-gate design — the core of lens 4's deterministic-guardrail concern.

### 3. Can AI Remediate Backend Failures Safely? GuardedAct with Blast-Radius-Aware Sandboxing (academic, Wanrong Cai, Tianyu Yu, Shaorui Pi, Xiaoxuan Sun, Wenrui Ma, arXiv, 2026-09-10)

**Why it matters:** GuardedAct interposes a blast-radius-aware simulation-and-verification layer between an LLM remediation agent and production microservices, executing only low-risk fixes automatically and routing risky ones to a human. Across five failure scenarios it reports an 87.4% recovery rate while cutting collateral damage by 79.7% versus direct LLM execution, at the cost of an average eight-second delay — a concrete, quantified architecture pattern for the specific high-stakes case of autonomous incident remediation.

**Source:** https://arxiv.org/abs/2609.11264 · **Library entry:** [2026-cai-guardedact-backend-remediation](../../../library/entries/2026-cai-guardedact-backend-remediation.md)
**Selected because:** a concrete simulate-then-gate control with a quantified safety/latency trade-off for autonomous production remediation — lens 6.
