## Today's developments

### 1. Accepted but Wrong: Silent Failures of LLM Code Repairs after API Migrations (academic, Xiaobo Chen, Genliang Zhu, Ziyuan Wang, Chu Wang, 2026-11-05)

**Why it matters:** A preregistered, quantified test of a release-gating
assumption builders make every day: checking an LLM-generated repair
against typical-input assertions. Across 73 real API-migration tasks, that
gate let 41% of wrong repairs through — but adding one edge-case input
drawn from the migration's own release note cut that to ~6.5%. A cheap,
concrete, and immediately applicable deterministic-guardrail fix.

**Source:** https://arxiv.org/abs/2611.08269 · **Library entry:** [2026-chen-accepted-but-wrong-silent-repair-failures](../../../library/entries/2026-chen-accepted-but-wrong-silent-repair-failures.md)
**Selected because:** High on evaluation/deterministic guardrails (lens 4)
— quantified, preregistered, and directly actionable.

### 2. Signed, Sealed, Leaked: Trust Beyond Signature for MCP Toolchains (academic, Yichiet Aun, Mohammed A. Alhartomi, Jing Jie Tan, Waqas Nadeem, Adeb Salh, Shankar Karuppayah, Sin Chee Tan, 2026-11-04)

**Why it matters:** Shows a signed MCP tool can still exfiltrate data past
an existing defense (Meta's MCPGuard-Dynamic), then proposes and proves
"germline execution" — ephemeral, data-scoped forked processes per
invocation — with a formal non-interference guarantee and a quantified
security/performance evaluation (zero unauthorized disclosures across 153
attack runs, 10–49ms latency). A named failure mode and a named fix for
anyone trusting MCP tool signatures alone.

**Source:** https://arxiv.org/abs/2611.06585 · **Library entry:** [2026-aun-germline-execution-mcp-toolchain-trust](../../../library/entries/2026-aun-germline-execution-mcp-toolchain-trust.md)
**Selected because:** High on tool use/MCP (lens 3) and
reproducibility/security (lens 6) — a concrete mechanism with a formal
guarantee, not a general warning.

### 3. Airlock: Bounding the Multi-Agent Blast Radius via Selective Online Containment (academic, Zhonghao Zhan, Javad Forough, Yefan Zhang, Krinos Li, Xiao Ma, Hamed Haddadi, 2026-11-04)

**Why it matters:** A concrete runtime for a problem every production
multi-agent system eventually hits: what to do with everything downstream
of an agent once it's known to be faulty. Combines permission-narrowing
with a provenance graph for forward containment and backward root-cause
tracing, evaluated at scale (1,832 testbed runs, 161 smart-home runs,
24,266 simulation records) against real A2A and LangGraph controls, not a
toy baseline.

**Source:** https://arxiv.org/abs/2611.06727 · **Library entry:** [2026-zhan-airlock-multiagent-containment](../../../library/entries/2026-zhan-airlock-multiagent-containment.md)
**Selected because:** High on observability/debugging (lens 5) and
governance (lens 6) — a named, evaluated containment pattern, not a
proposal.
