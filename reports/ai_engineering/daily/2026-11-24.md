## Today's developments

### 1. AgentBouncer: Defending Software Engineering Agents via Dynamic System-Call Mediation (academic, Pascal Joos, Michael Pradel, 2026-11-24)

**Why it matters:** A runtime system-call gate with an LLM arbiter cuts attack success from 99.41% to 10.59% against four attack vectors — 18 to 74 points better than competing defenses — while blocking only 0.25% of benign tool calls and adding just 47 seconds and $0.0036 per task, versus 4.5x the time and 9.6x the cost for the closest existing defense. A deployable, measured security control for any agent runtime.

**Source:** https://arxiv.org/abs/2611.30621 · **Library entry:** [2026-joos-pradel-agentbouncer-syscall-mediation](../../../library/entries/2026-joos-pradel-agentbouncer-syscall-mediation.md)
**Selected because:** a concrete runtime defense with quantified attack-success reduction and measured cost/latency overhead against a named baseline — lens 6 (reproducibility, security and governance).

### 2. Oops!... I Parsed It Again: Tool-Call Smuggling Against LLM Agents (academic, Santos-Grueiro et al., 2026-11-24)

**Why it matters:** Names a new, demonstrated vulnerability class — a guard approves one tool call while the executor runs a different one, because the same JSON bytes parse differently across components, differential-tested across 17 parser configurations (even two official MCP SDKs disagree). Live exploits cancel another customer's reservation and bypass a file-creation block while the audit log shows only the approved call. The proposed single-parse, schema-filtered defense reportedly stops all 7,412 crafted inputs tested.

**Source:** https://arxiv.org/abs/2611.30624 · **Library entry:** [2026-tool-call-smuggling-against-llm-agents](../../../library/entries/2026-tool-call-smuggling-against-llm-agents.md)
**Selected because:** names and demonstrates a previously unlabeled tool-permission bypass class with a measured defense — lens 3 (tool use and MCP) and lens 6 (security).

### 3. Does the Agent's Map Match the Territory? Architectural Claims in AI Agent Context Files and Their Fit with the Code (academic, Bachan Ghimire, Daniela Damian, 2026-11-23)

**Why it matters:** Checks 41,090 path claims and 184 dependency rules across 3,602 CLAUDE.md/AGENTS.md-style context files in 3,346 projects against the actual code: paths are fairly reliable (about 2.2% genuinely wrong, comparable to READMEs), but 18% of dependency/import rules were already violated when written and nearly all stayed violated — context files are decent maps but weak, unenforced rulebooks.

**Source:** https://arxiv.org/abs/2611.29916 · **Library entry:** [2026-ghimire-damian-agent-context-files-architecture-fit](../../../library/entries/2026-ghimire-damian-agent-context-files-architecture-fit.md)
**Selected because:** a large-scale, directly actionable measurement of how trustworthy agent-context-file claims are — lens 2 (harness and context engineering).
