## Today's developments

### 1. Aegis OS: A Transactional Multi-Tenant Operating System Runtime for Eliminating Authorization Fatigue in Autonomous Coding Agents (academic, Hui Zhao, 2026-10-22)

**Why it matters:** Replaces the usual binary choice for coding-agent
security — confirm every action (45-57% of tool calls interrupted, per the
paper) or run unrestricted (full credential/filesystem exposure) — with a
kernel-enforced transactional workspace. Evaluated across 1,500 controlled
calls and 28,087 real calls from 52 sessions: confirmation prompts fell
90-99%, and attack success fell from 100% to 0% across 80 attacks in eight
categories. A concrete, measured architecture, not a general warning.

**Source:** https://arxiv.org/abs/2611.08516 · **Library entry:** [2026-zhao-aegis-os-transactional-agent-runtime](../../../library/entries/2026-zhao-aegis-os-transactional-agent-runtime.md)
**Selected because:** High on reproducibility/security (lens 6) and agent
architecture (lens 1) — quantified before/after evaluation on both
controlled and real sessions.

### 2. When Instruction Files Go Stale: Documentation Debt and Hidden Cost in Coding Agents (academic, Tural Mehtiyev, Biruk Tadesse, Lawrence Arkoh, Wesley Assunção, 2026-11-06)

**Why it matters:** A controlled study (732 trajectories, two models, three
real stale instructions from active open-source projects) showing agents
follow stale AGENTS.md/CLAUDE.md-style guidance even when correct
information is available elsewhere, costing extra tool calls silently and
never self-repairing the file — a cost that task-success-only evaluation
misses entirely. Directly actionable: audit and correct instruction files
rather than assume agents route around staleness.

**Source:** https://arxiv.org/abs/2611.09802 · **Library entry:** [2026-mehtiyev-stale-instruction-files-documentation-debt](../../../library/entries/2026-mehtiyev-stale-instruction-files-documentation-debt.md)
**Selected because:** High on harness/context engineering (lens 2) —
quantified, controlled, and squarely on a problem this project's own
CLAUDE.md-maintenance practice faces.

### 3. Agents on the Patch Path: Mining AI-Associated Security Remediation in GitHub Security Advisories (academic, Claudio Segal et al., 2026-11-06)

**Why it matters:** The first large-scale empirical evidence (469
candidate advisories across 189 repositories, with a reusable detection
pipeline) that coding agents are already part of real-world security
patching, including high/critical-severity fixes — Claude the most
frequently observed tool. A specific, falsifiable data point (mixed
review-lag findings) against both "agents slow review down" and "agents
have solved security" narratives.

**Source:** https://arxiv.org/abs/2611.09808 · **Library entry:** [2026-segal-agents-patch-path-security-remediation](../../../library/entries/2026-segal-agents-patch-path-security-remediation.md)
**Selected because:** High on AI-assisted software development (lens 7) —
large-scale mining evidence, not anecdote or opinion.
